## 2. Why loops plateau (evidence)

Board-wide (121 reviews, 23 columns, read from the tab's stored board):
- **78 of 100 consecutive review pairs gave exactly the same score.** 16 went up and 6 went down. 108 of 121 scores are 3.0 or 3.5.
- **43 of 121 reviews (36%) say the reviewer's own measurements were "blocked by policy" or "unverified".** The reviewer's command to measure pixels was refused, so it couldn't confirm the numbers the author sent.
- Each review lists on average **7.0 faults and 8.5 fixes**. The author spreads one round over all of them.

Causes, strongest first:

1. **Half-star scores hide real progress.** Measured with the tab's own `metrics.js` (section 4), Scree slopes rounds 3 to 7 all scored 3.0. Over those rounds the brightness spread (luminance SD) rose from 31.9 to 42.6 (reference 42.9), fine detail rose from 8.6 to 10.1, edge density rose from 3.6% to 5.2% and edge overlap rose from 0.23 to 0.27. The reviewer saw these changes too ("blocker partly addressed" in rounds 4, 6 and 7). A gain smaller than one half star is invisible to a rule that needs a strictly higher score, so `robust.js` (PLATEAU_STOP = 4, strict gain) stops columns that are still improving.
2. **The reviewer is anchored on the history.** Every review request lists "Earlier scores: 3, 3, 3". The reviewer guide (2.2 step 4) also says "Compare with the earlier scores … do not move the score without a reason you can name in numbers". But the reviewer's measuring commands are often blocked (above), so it seldom has the numbers it is told to need, and the score stays where it was. 63 of 121 summaries say "unchanged".
3. **The loop always builds on the last round, never on the best.** Caves round 2 added "triangular surface artifacts", round 3 "roof lighting regressed", and round 5 brought large sheared slabs (see the sheet). Each later round still started from the previous one, so a fix and a new fault cancelled out at 3.0. Rolling hills round 2 added "near-black blotches … a visible regression".
4. **Broad fix lists.** With 8-10 fixes a round, authors make small progress on many items. The PLATEAU block (1.5.20) asks for a change of approach, but its stop comes after 4 rounds whatever the measured trend.
5. **A wrong reference blocks one column outright (Rolling hills).** Its reference is a studio tile on grey (`proc-refs/terrain-rolling-hills.jpg`), but every capture is a walker's-eye scene, as the scene class requires. Every review says "Reference is an elevated tile, limiting scene matching". The measured colour histogram distance stays at 0.55-0.62, against 0.09-0.33 for the other two columns. No loop strategy can fix this. The column needs a scene reference, which Chris decides (we never change live references).

The noise checks (step 0) are in section 5.1. One measured fact already bears on noise: the reviewer gave 3.0 to five Caves pictures whose measured colour distance ranged from 0.09 to 0.17 and whose edge overlap ranged from 0.41 to 0.51. That looks more like a sticky score than random noise, but only the re-scores can show the spread.

## 3. What was built (Asset Studio / Evani.commons 1.5.27)

There is a per-column **Loop** picker on each column, plus the `loop_trial` action. **Standard** (today's loop) stays the default for every column. Nothing changes until the picker or a trial says so. The five parts can be switched on separately:

| Part | What it does | combined | lean | best3 | blocker |
|---|---|---|---|---|---|
| best3 | The author makes 3 distinct variants from the best version. The reviewer scores each picture on its own, then ranks them. The winner becomes the best version. | ✓ | | ✓ | |
| avg2 | Every picture is scored in 2 separate review passes and averaged (0.25 steps). The second pass lists the pictures in reverse order. Earlier scores are hidden from the reviewer. | ✓ | ✓ | ✓ | |
| blocker | The first line of the review must be "Blocker: … \| Reference: … \| Render: … \| Fixed when: <measure and number>" (the tab refuses a review without it). The author fixes only the blocker and rolls back if its number gets worse. | ✓ | ✓ | | ✓ |
| metrics | Before the review request goes out, the tab measures every capture against the reference itself: colour histogram distance, luminance mean/SD, fine detail, edge density and overlap, horizon height, silhouette overlap for objects, and the 3x3 cell that differs most. The numbers go to the reviewer and the author. Close-up crops are added as `close_path`. | ✓ | ✓ | | ✓ |
| planner | After 2 rounds without a gain of 0.25 or more, the author lists 3 different approaches before writing code. With best3, each variant tries one of them. Every round builds from the best version, never a worse one. | ✓ | ✓ | | |

Trial rules: `loop_trial { column, strategy, rounds ≤ 5 }` runs a stopped column through its own author and reviewer, then stops it ("trial finished"). Only one trial column runs at a time, so queued sends and other columns keep their helper places (the tab's 3-helper limit). Trial rounds are never auto-sent (`trustedBest` skips them), and authors are told not to fold them into the library. A `standard` trial adds extra baseline rounds under the same cap, without the plateau stop. `noise_check { column, round, times }` has the column's own reviewer re-score a finished round with `submit_rescore`. It changes nothing in the column. The `trial` read gives every pass, average, winner, measured numbers, the cost in minutes and passes, and the noise spread.

Trial work goes first (1.5.32, Chris 2026-11-08: "Yes, let the tests go first"). While a column runs a `loop_trial` trial, or a `noise_check` or `scoring_check` is under way, that work takes the next free helper place before any other column. This covers the trial's author, its review and the check request, ahead of other columns' reviews and authors. Packers keep their own reserved place, nothing running is interrupted, and "At once" is unchanged. When the trial or check ends or is cancelled, normal order returns by itself. Test: `node tools/studio/commons-tab-test/trial-priority.mjs` (a trial and a noise check each jump 20 waiting columns).

## 7. The categories arm (v1.5.29): a scoring change, kept apart from the loop changes

Chris, 2026-11-08: two Jagged rock renders and two Caves renders each got the same half-star grade although one of each pair is clearly better. He chose scoring in categories. Research: `.vibedeck/research/2026-11-08-scoring-design-for-a-vision-model-judge-asset-stud.md`; the rules are in `docs/ASSET_STUDIO_GUIDE.md` 2.3c.

- **What it changes:** only the scoring. Five categories, 0-20 each, with written anchors (silhouette and shape 25%, structure and separation 25%, material and texture 20%, colour 15%, lighting and scale 15%), a total out of 100, stars = total / 20 to the nearest half; a blind review; a closer check against the best version in both orders (tie allowed); the tab's measurements as a veto only; stop after 4 rounds without a new best. The author gets every category's score and note, the weakest as "focus this round", and each category's trend against the best version.
- **What it keeps:** today's standard loop (no best-of-3, no averaged passes, no blocker-only rule, no new-plan rule), so it compares with the `standard` arm and the loop arms without mixing the two changes.
- **How to run it:** `loop_trial { column, strategy: "categories", rounds: 5 }` on a stopped column, one trial column at a time, on the same 3 columns as the other arms: **#29 Caves, #27 Scree slopes, #23 Medium rocks**. Read `trial`: each round's `categories` (scores, notes, focus, trend, `vs_round`, `picks`, `pairwise`, `became_best`, `veto`) and `trial.strategy` "categories". Trial rounds are never auto-sent. The Scoring picker of every column stays classic: Chris decides after the trial.
- **Calibration with Chris's pairs:** `scoring_check { column, pictures: [better, worse] }` has the column's own reviewer score the two pictures in categories and run the closer check both ways (changes nothing).
