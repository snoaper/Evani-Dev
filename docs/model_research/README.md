# Evani.Model clean-room research (M0)

Clean-room design notes for Evani.Model, written 2026-10-15 for milestone M0 of the brief (docs/EVANI_MODEL_BRIEF.md). Builder agents implement from the brief and these notes only, and never open third-party source code for the functionality they build (brief, originality 2).

## How these notes were made (clean-room record)
- Read: the brief; this workspace's STAGES.md, DECISIONS.md, Cargo.toml, catalog/looks.json and tiers.json, docs/GEOCHECK.md, docs/LIVE_API.md conventions, docs/LOOP_API.md headings (on the `evani-loop` branch), and the kart racer's own kart drawing code and data (our own code).
- Read for ideas: the arXiv abstracts and HTML papers of CADSmith, LL3M, ShapeCraft, OmniPart, PartField, DiffCSG, SigLIP 2, aDSL, FullPart, 3D-GPT; the Khronos KHR_mesh_quantization specification; the TRELLIS.2 README (hardware, licence and output description only); licence statements of CoACD, OmniPart and PartField from search results. Other techniques (Inigo Quilez's articles, Ju et al. 2002 and successors, Hansen's CMA-ES tutorial, MikkTSpace description, quadric simplification, LSCM, successive halving) are summarised from the published papers and articles as we understand them.
- Read at the start of M1 (the review noted that M0 skipped them): docs/KIT_PROCESS.md, the kit build process, which matters for how compiled models enter a kit (M5, test J) and has no modeling content; and the genre catalog (catalog/genres.json, a single file rather than the brief's `catalog/genres/` folder), which only fixes which look each genre may use (the kart racer's `toon`, the look `toon_chunky` sits on, decision D6). Neither changes the design.
- Not opened: any third-party source code (no repository source files, no MikkTSpace reference source, no meshoptimizer, xatlas, CoACD, TRELLIS.2, OmniPart, PartField or aDSL code). No third-party files were added to the repository. The notes contain no code.
- Earlier prior-art reports in .vibedeck/research/ cover the engine stack, the Evani Loop, live code swapping, the look guard, three.js benchmark scenes, WebXR and agent guidance; none covers 3D modeling, so nothing was reused from them. docs/model_research/ did not exist before this milestone.

## Known / ours / why / result

| Component | Known approaches | Ours | Why it should be better | Result |
|---|---|---|---|---|
| Intent document | Language model writes Blender Python or CAD code (LL3M, 3D-GPT, CADSmith); relational DSL co-designed with the agent (aDSL); part graph per prompt (ShapeCraft) | Declarative text with units, bare adjectives and calls; closed, versioned vocabulary checked before anything runs; template defaults; canonical JSON twin | Agent writes concepts, machine places numbers; most errors impossible to write; ~150 tokens per kart | to measure in M1 (parse/validate) and M5 (tokens vs baseline F) |
| Style profiles | Style from prompts or images; language model guesses parameter values; embedding scores | Per-style data: adjective → measure ranges, perceptual step sizes, bevel and proportion rules; sweep sheets, critic proposal, one approval per style; `toon_chunky` as a profile on the `toon` look | Words become reproducible numbers; edits verifiable; Chris approves once per style | to measure in M3 (edit success ≥ 95%, ablation "word calibration") |
| Class templates | Learned part structure (FullPart, OmniPart, TRELLIS.2); hand generators with raw parameters (3D-GPT); graph from scratch per prompt (ShapeCraft) | Data templates in 5 families: parts with roles, relationships, gameplay anchors, default musts, typical views, named measures; extended by approvals | Knowledge fills gaps; parts and anchors the game needs; valid space from call one | to measure in M1 (kart) and M3 (all 18 classes from two-line intents) |
| Part generators | DCC primitives and modifiers; learned part generators (OmniPart, FullPart); retries per part (ShapeCraft) | One interface: field builder, analytic anchors, bounds and Lipschitz bound, natural parameterisation, collision hint, thin-feature mesh; external services clipped to part boxes | Fields blend and never fail; exact anchors; per-part resolution without training | to measure in M1 (per-generator tests, throughput) |
| SDF back end | Quilez's distance functions and operators; sphere tracing; mesh CSG; DiffCSG rasterised CSG | Typed SDF graph with Lipschitz bookkeeping; sweeps, lathes, lofts, subdivision cages; one GPU interpreter for all candidates plus optional specialised WGSL; deterministic CPU path with own transcendentals and exact forward-mode gradients | Booleans never fail; domain ops safe to trace; many candidates per dispatch; identical CPU results everywhere | to measure in M1 (CPU, determinism) and M2 (GPU throughput) |
| Constraint solver | Relational operators checked by a critic (aDSL); learned box layouts (OmniPart, FullPart); exact checks after the fact (CADSmith, which missed joint gaps) | Anchors as frames; analytic solve in dependency order; surface-aware rests_on/flush_with by field queries; own Levenberg-Marquardt for cycles and inequalities; musts as constraints or field-maths checks; connectivity default | Contact and clearance exact, so CADSmith's tiny gaps cannot pass; microsecond solves | to measure in M1 (unit tests incl. 1 mm gap cases; solve time) |
| Search and scoring | Few expensive attempts plus critic rounds (ShapeCraft, LL3M, aDSL ~190 s per round); quasi-random sequences; successive halving and Hyperband; image-text scores (SigLIP 2) | Prefix-stable scrambled quasi-random sampling through priors; one volume pass gives three silhouettes and measures; rungs 32³ → 64³ → 128³; must-gates first; a fixed schedule per level (no clock); GPU interval scores with close calls settled on the CPU; early stop on CPU scores; compact scorecards | Hundreds of candidates in seconds; cheap first rung; GPU speed with exactly the CPU-only result | to measure in M2 (8 karts IoU ≥ 0.9 within speed targets on Standard and Lite) |
| Refinement | CMA-ES (Hansen); differentiable CSG rasterisation (DiffCSG) | Own CMA-ES with bounded transform and feasibility-first ranking; alternative analytic silhouette-boundary gradient from exact field derivatives; keep the faster at equal quality | Gradient-free robustness by default; exact gradients without soft rasterising as a contender | to measure in M2 (time to IoU 0.9 per tier, both methods) |
| Learned priors | Network weights (OmniPart, FullPart, TRELLIS.2); Bayesian optimisation; exemplar retrieval (LL3M) | Per (class, style) mixture over approved parameter vectors, conditioned on adjectives, with a 30% uniform floor; deterministic warping; prior hash in the recipe | Improves after one approval, readable, keeps variety | to measure in M3 (candidates to target falling across run order; ablation "priors") |
| Language edits, retrieval, verification | Retrieval over API docs (LL3M −26% errors; CADSmith); vision-model edit verification (LL3M, ~59% single-instruction edits); relational repair (aDSL) | Edits as intent diffs; local re-search; verification by measure vectors and part hashes with explained couplings; versions and undo; analogies through the library; own lexical index over a closed vocabulary | Exact edit checks; locality proven by numbers; 1 s edits through content-hash caching | to measure in M3 (180-edit benchmark ≥ 95%; ablations "retrieval", "edit verification") |
| Critic loop | Stronger judge on renders plus kernel metrics (CADSmith, Opus over Sonnet); critic and verifier agents (LL3M); plan-execute-critic (aDSL ~4.25 rounds) | Critic packet (intent, scorecard, exact discrepancies, optional one sheet); critic decides taste only; maths decides space; rethink construction after 2 failed rounds | Small packets make a stronger critic affordable; spatial errors never reach taste review | to measure in M3/M5 (rounds, tokens; ablation "stronger critic") |
| Surface relief | Bump/normal mapping; baked displacement (no tessellation in WebGPU); parallax; procedural noise; curvature/AO wear masks; learned textured generators | Layers = region selector × pattern × amplitude in metres on natural parameterisations; own pattern library; per-tier split by wavelength into geometry / normal map (+height) / shader recipe; readability under the toon bands; wear plausibility | One definition, three consistent deliveries; no UV work for the AI; no unreadable bytes | to measure in M4 (tread, bolts, panel lines correct on every tier; bytes per tier) |
| Meshing | Marching cubes; extended MC; Dual Contouring of Hermite data (Ju et al. 2002); dual MC; manifold DC; intersection-free DC; surface nets; learned DC | Own dual method on an adaptive octree: exact Hermite data, crease hints from generators, multi-patch cells for manifoldness, vertices clamped to cells, validator with local re-extraction, budgeted refinement by curvature, relief, screen size and silhouette | Feature edges by knowledge, not guessing; watertight and manifold by construction; triangles where the camera looks | to measure in M1 (test A on every model; accuracy vs marching cubes control) |
| Per-tier LODs | Quadric edge collapse (Garland-Heckbert; meshoptimizer); progressive meshes; impostors | Re-extract per tier; drop parts and relief by meaning and pixel size; protect silhouettes for the class's typical views; measure and rebalance | ≥ 30% fewer triangles at equal silhouette error (test D target) | to measure in M1 (LOD files) and M5 (vs meshoptimizer) |
| Collision | Convex decomposition of finished meshes (V-HACD, CoACD); hand proxies; the kit's hand-made capsule | Analytic proxy per part from parameters, grouped by graph, fit-checked and upgraded; moving parts named; game-shaped proxies (kart capsule) | Few exact proxies in microseconds; matches the kit's rule | to measure in M1 (proxies exported) and M5 (vs CoACD) |
| Normals, tangents, UVs | Ray-cast baking with cages; MikkTSpace convention; LSCM, ABF++, xatlas-style charting and packing | Exact gradient normals with crease splits; MikkTSpace implemented from its description; per-texel Newton projection onto the field, no rays; charts from natural parameterisations with seams at part boundaries and hidden edges; own conformal fallback and skyline packing | No bake artefacts; invisible seams by meaning; near-zero distortion for common parts | to measure in M1 (tangents vs Blender, seams test) and M4 (normal maps) and M5 (vs xatlas) |
| glTF output | glTF 2.0 core; KHR_mesh_quantization; compression extensions; MSFT_lod or files per level; Khronos validator | Own .glb writer, one file per tier, 16-bit positions, 8/16-bit normals, 8-bit tangents, 16-bit UVs in 0..1, part-tree nodes, anchor and collision nodes, `extras.evani` metadata, byte-deterministic | Smaller per-tier downloads; metadata the kit needs; meaningful hashes | to measure in M1 (validator clean; bytes per tier) |
| Hardware and determinism | Vendor-only stacks (TRELLIS.2 needs CUDA, Linux, 24 GB); portable wgpu; IEEE 754 basic ops deterministic, maths libraries and GPUs not | Detection plus memory table and 50 ms throughput calibration (wgpu reports no GPU memory); tier stored per machine; `auto` level from tier and budget only; budgets counted in work, never time; tiles that halve on failure; GPU explores, CPU decides (interval rule, sentinel-checked error bound); own transcendentals and SHA-256 | Runs on every machine; same request at the same level gives the same bytes everywhere; same tier on `auto` gives the same model | to measure in M2 (tests E, H partial) and M5 (full hardware matrix) |
| MCP tools | Code-execution servers with screenshots; multi-agent code and render exchange; evani-live's compact JSON conventions | Eleven tools with underscore names (dotted in docs), two-call happy path, compact replies with fix lines, images only on request as one sheet, no vertex data, time budgets in arguments | ≥ 5x fewer tokens and calls than baseline F (test D target) | to measure in M5 (benchmark, 3 recorded sessions) |
| Integration | Learned part segmentation (PartField); separate generation and import pipelines | Validator, our own meshcheck (geocheck cross-check in the bench tool) and musts until evani-convert exists; metadata guides the converter; anchors read by the kit; library items with full provenance, uploaded only by Chris's click; own field-based part splitter for imports; recipe-only delivery designed | Integration by reading data, not guessing; reproducible library items | to measure in M5 (test J, geocheck zero untagged issues) |
| Sheets and previews | Headless offline renderers (Blender); the engine's own capture (needs the game to load the model); sphere tracing (Hart); edge-function rasterisation (Pineda); cel bands and outlines from depth and normal jumps | Own CPU renderer: quick preview mesh or the compiled tier for coverage, fixed-point 4-sample rasteriser, exact per-pixel field normals or the tier's normal map and micro-detail, the look's ramp read from its data with a drift test, own bitmap font and PNG writer; five sheet kinds plus calibration, reference and test K sheets | Runs inside the call on any machine; identical bytes, so approvals pin the exact picture; shows relief the game cannot draw yet, per tier | to measure in M1 (sheet time, identical hashes, Blender sanity check) and after Stage 3 (agreement with in-game capture) |

## Sources that contradict or stretch the brief (flagged, design not changed)
1. **`toon_chunky` is not a look in catalog/looks.json** (the kart racer uses `toon`). Proposed: a modeling style profile on the `toon` look (note 02, decision D6).
2. **wgpu is browser-only in this workspace** (features `webgpu`, `wgsl`, `std`); a native tool needs Vulkan, Metal and DX12 backends (note 18, decision D1).
3. **wgpu reports no GPU memory size**, which the Pro rule (24 GB) needs; estimated from the driver tool, a device table and a throughput calibration (note 18).
4. **Identical hashes across tiers vs different candidate counts per tier** (tests E and H): resolved by defining the promise as "same request at the same level, same bytes", with `auto` resolved from the tier and budget only, so it repeats within a tier but may differ across tiers (notes 07, 18, decision D5). The brief's "fixed time" is kept by choosing the level up front, never by stopping on the clock.
5. **The 8 Sugarpeak karts share one shape today**; only colour (body and suit) differs, which Evani.Model does not model (no colour). The 8 references are therefore identical unless rival variants are defined (tests/model_bench/README.md, decision D4).
6. **The brief's example `fit_box: [1.3, 0.8, 0.7] m`** is far smaller than the game's kart (about 3.1 m long, 2.2 m wide over the wheel hubs, 1.27 m tall to the wing without the driver, measured from draw_kart). The example stays as written in MODEL_API.md; benchmark karts use the game's scale. We read `fit_box` as length, width, height along the model's forward, right and up axes, which fits the example.
7. **evani-convert does not exist yet** (Stage 3), so M5's integration and test J wait for it (note 20, decision D11).
8. **Licences of the optional plug-in generators**: TRELLIS.2 is MIT but depends on NVIDIA libraries (nvdiffrast, nvdiffrec) whose licence is non-commercial, and needs Linux and 24 GB of GPU memory; OmniPart is MIT but includes code derived from PartField under the NVIDIA Source Code License (decision D8).
9. **MCP tool names with dots** (`model.make`) break clients that only accept letters, digits, `_` and `-`; registered with underscores, as evani-live does (note 19, decision D10).
10. **docs/LOOP_API.md** is named as an internal reference but is only on the `evani-loop` branch, not on m1-foundation.
11. **The differentiable-rendering alternative is substituted.** The brief asks to evaluate "a differentiable-rendering fit" against our evolution strategy; note 08 proposes our own analytic boundary-gradient fit of the silhouette instead (gradients from the field at the silhouette boundary, no rasteriser to differentiate). It should be faster and exact for our fields, and it is still evaluated against the evolution strategy as the brief asks, but it is not differentiable rendering in the usual sense.

Confirmed, not contradicting: CADSmith's joint-gap failure (its figure 6, a quadcopter frame with F1 0.963 and IoU 0.985 that passed every check) and its stronger judge (Claude Opus over Sonnet); LL3M's 26% error reduction from retrieval.
