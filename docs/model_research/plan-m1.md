# M1 build plan, hardware matrix plan (H) and originality scan plan (I)

M0 plan, 2026-10-15. M1 starts only after Chris approves M0 and decides the items in plan-decisions.md (D1 and D2 block T1's GPU feature and the MCP server; nothing else blocks the CPU work).

## M1 goal (brief)
"Compiler: intent document, shape back end, constraint solver, procedural generators, compiler. Done when a kart written as intent compiles to valid glTF with LODs, anchors and collision, passing its tests and section A."

M1 has no search (M2): `make` compiles one candidate at the centre of every adjective range (or the numbers given), so the kart intent compiles deterministically with the draft toon_chunky profile.

**Section A in M1** (flag, decision D15): determinism, must kinds, mesh validity and normal maps (of the smooth field, without relief) are tested in M1. Relief readability needs relief (M4) and adjective-edit locality needs edits (M3); M1 tests the compiler-level part of locality instead (changing one part's parameter leaves every other part's compiled pieces byte-identical), and the full tests are added in M3 and M4.

## Ordered tasks
Sizes: S (under a day of agent work), M (1 to 2 days), L (2 to 4 days), XL (4 days or more). Worker suggestions follow the brief's routing: Opus at high effort for architecture, solver and search; lighter models for patterns, templates, docs and test data. Every task ends with `cargo xtask check` clean (built at CARGO_BUILD_JOBS=2, below-normal priority on the shared PC) and a commit.

Reports are merged on the dev PC. Cloud machines are started and stopped by the orchestrator with Chris's approval of the spend.

## Originality and licence scan plan (test I)
Run before every milestone sign-off by a scanning agent that is not a builder.
1. **Licence scan of our files.** ScanCode Toolkit (Apache-2.0, run separately) over `crates/evani-model`, `tools/evani-model`, `tools/model-bench-ref`, `tests/model_bench` and `docs/model_research`: no third-party licence texts, copyright notices or vendored files. Target: nothing found except our own.
2. **Dependency licence check.** `cargo deny check licenses` (cargo-deny, MIT or Apache-2.0, installed as a tool) on the evani-model crates: only the approved dependencies, all with permissive licences.
3. **Code similarity, same language.** JPlag (GPL-3.0, Java; run separately, supports Rust) comparing our crates against a corpus of Rust projects in the same domain, cloned read-only into a folder outside the repository that builders never open (for example Rust SDF, implicit-surface, isosurface, surface-net, CMA-ES, glTF and MikkTSpace-port crates). Any pair above 30% similarity, or any matched block longer than about 12 lines, is investigated and rewritten.
4. **Cross-language ports.** For C and C++ projects (MikkTSpace reference, meshoptimizer, xatlas, CoACD, Manifold, libfive and similar), a distinctive-token check: a small script of ours lists our numeric constants with four or more significant digits, unusual identifiers and comment phrases, and searches the corpus for them; every hit is reviewed by hand. Dolos (MIT) is a second opinion where it supports the language.
5. **Model weights and data.** Check that no weights, datasets or third-party meshes are in the repository (file types and sizes).
6. **Record.** The scan report (tool versions, corpus list with commits, results, actions) goes into the milestone report; the corpus folder stays outside the repo.

This PC has no Java or Python installed today; JPlag needs Java and ScanCode needs Python, both installed in the scratch tools folder outside the repository.
